## BAGIAN 0 — CARA KERJA SISTEM SECARA GLOBAL

- Website: Next.js App Router. Semua fitur diakses lewat REST API di bawah /api.
- Autentikasi: cookie bernama `skelzhub_session` (httpOnly). Login menghasilkan cookie; semua request berikutnya membawa cookie otomatis.
- Media (gambar/video/audio): disimpan sebagai baris Media di database. Aplikasi TIDAK menerima file base64 di JSON. Sebagai gantinya, semua objek berisi field URL berupa STRING "/api/media/<mediaId>". Aplikasi tinggal memuat URL itu (relative terhadap alamat server).
- Upload file dilakukan dulu ke endpoint upload (dapat mediaId), lalu mediaId dipakai untuk membuat post/story/pesan/avatar.

## BAGIAN 2 — KONVENSI GLOBAL API

- Semua respons error berbentuk: `{ "error": "pesan bahasa Indonesia" }` dengan status 400/401/403/404/409/429.
- Respons daftar SELALU dibungkus objek: `{ posts: [...], nextPage: number|null, hasMore: boolean }` — TIDAK PERNAH array telanjang. Sama untuk comments dan users.
- Media selalu sebagai STRING URL: `"/api/media/<id>"` pada field bernama `media`, `avatar`, `audio`, `postMedia`. Gabungkan dengan alamat server.
- UserBrief (dipakai di semua tempat user disematkan): `{ id, username, displayName, avatarColor, avatar (string|null), role ("USER"|"ADMIN"|"OWNER") }`
- PostDTO: `{ id, caption, media (string|null), type ("IMAGE"|"VIDEO"), createdAt, author: UserBrief, likeCount, commentCount, repostCount, likedByMe, savedByMe, repostedByMe, repostOf (PostDTO|null), previewComments (CommentDTO[], maks 2) }`
- CommentDTO: `{ id, text, createdAt, parentId, replyTo: UserBrief|null, author: UserBrief }`
- UserDTO (profil): `{ id, username, displayName, bio, avatarColor, avatar, isPrivate, role, lastSeenAt, postCount, followerCount, followingCount, isFollowing, followStatus ("NONE"|"PENDING"|"ACCEPTED"), isMe }`

## BAGIAN 3 — ENDPOINT AUTENTIKASI

### POST /api/auth/login
Body: `{ username, password }` (username boleh username ATAU email).
Dua hasil:
- Akun tanpa email terverifikasi → session langsung: `{ step: "done", user: { id, username, email, displayName, bio, avatarColor, avatar, isPrivate, role } }`
- Akun dengan email (2FA) → `{ step: "code", userId, email (dimasking spt "sk••••@gmail.com"), emailSent, emailConfigured }` — session BELUM dibuat. Lanjut ke verify.
Error 401 kredensial salah; 403 kena ban.

### POST /api/auth/login/verify
Body: `{ userId, code }` (kode 6 digit, berlaku 10 menit, maks 5 percobaan).
Sukses → session dibuat → `{ step: "done", user: {...} }`.

### POST /api/auth/register
Body: `{ username, displayName?, email, password }`. Username regex `[a-zA-Z0-9._]{3,20}`; password min 6.
→ `{ step: "done", user: {...} }`. 409 kalau username/email sudah dipakai.

### POST /api/auth/logout
Tanpa body. → `{ ok: true }`.

### GET /api/auth/me
→ `{ user: {...}|null }`.

### POST /api/auth/forgot-password  |  POST /api/auth/reset-password
Body reset: `{ email, code, newPassword }` → `{ ok: true }`.

## BAGIAN 4 — POSTS

### GET /api/posts
Query: `feed` = home | following | explore | shorts | saved | reposts; `username` (profil); `page` (mulai 0); `limit` (default 12, maks 50).
→ `{ posts: PostDTO[], nextPage, hasMore }`.

### POST /api/posts  (login)
Body: `{ caption?, mediaId }` ATAU `{ caption?, repostOfId }`. → `{ post: PostDTO }`.

### GET /api/posts/[id]  →  `{ post: PostDTO }`  (403 kalau akun privat & bukan pengikut)

### DELETE /api/posts/[id]  (pemilik/admin)  →  `{ ok: true }`

### GET /api/posts/[id]/comments  →  `{ comments: CommentDTO[], nextPage, hasMore }` (page/limit)
### POST /api/posts/[id]/comments  (login)
Body: `{ text (maks 500), parentId? }` → `{ comment: CommentDTO & { isMine: true } }`.
### POST /api/posts/[id]/like  → `{ liked: boolean, likeCount }` (toggle)
### POST /api/posts/[id]/repost → `{ reposted, repostCount }` (toggle)
### POST /api/posts/[id]/save  → `{ saved: boolean }` (toggle)
### POST /api/posts/[id]/report Body: `{ reason }` → `{ ok: true }`

CATATAN: kalau [id] adalah repost, semua interaksi otomatis diarahkan ke post ASLINYA oleh server.

## BAGIAN 6 — CHAT (percakapan & pesan)

### GET /api/conversations  (login)
→ `{ conversations: [ { id, user: UserBrief & { online, lastSeenAt }, lastMessage (string maks 80|null), lastMessageKind, lastMessageDeleted, lastMessageAt, lastMessageMine, unread } ], unread (total) }`

### POST /api/conversations  Body: `{ username }` → `{ conversationId }`

### GET /api/conversations/[id]/messages  (login, peserta)
Dua mode:
1. Riwayat: `?page=0&limit=40` → `{ messages: MessageDTO[], other: Presence, nextPage, hasMore }`
2. POLLING: `?since=<ISO datetime>` → mengambil semua pesan dengan updatedAt > since (mencakup pesan baru + diedit + dihapus + reaksi berubah). → `{ messages: MessageDTO[], other: Presence, mineLastReadAt }`
Mode polling MENANDAI pesan masuk sebagai dibaca.
MessageDTO: `{ id, text, kind ("TEXT"|"IMAGE"|"VIDEO"|"VOICE"), media (string|null), mine (boolean), createdAt, readAt, editedAt, deleted (boolean), updatedAt, replyTo: { id, text, kind, senderName, senderMine, deleted }|null, reactions: [ { emoji, count, mine } ] }`
Presence (other): `{ user: UserBrief, online, lastSeenAt, typing }`

### POST /api/conversations/[id]/messages
Body: `{ text? (maks 1000), mediaId?, replyToId? }` → `{ message: MessageDTO }`

### PATCH /api/conversations/[id]/messages
Body: `{ messageId, text }` (hanya pesan teks sendiri) → `{ message: MessageDTO }`

### DELETE /api/conversations/[id]/messages?messageId=xxx → `{ ok: true }` (soft delete)

### POST /api/conversations/[id]/messages/react
Body: `{ messageId, emoji }` — emoji yang diizinkan: ❤️ 👍 😂 😮 😢 🔥. Toggle: kirim sama = hapus. → `{ ok: true, messageId, emoji: string|null }`

### POST /api/conversations/[id]/typing → `{ ok: true }` (kirim tiap ~2 detik saat mengetik; kadaluarsa 5 detik)

POLA POLLING WEB (tiru di Android): daftar percakapan tiap 2 detik; pesan aktif `?since=` tiap 1 detik; kursor = updatedAt pesan terbaru; heartbeat online `POST /api/me/heartbeat` tiap 25 detik.

## BAGIAN 7 — MEDIA & UPLOAD

### GET /api/media/[id]  — BUKAN JSON: file biner gambar/video/audio.
Dukung header `Range` → 206 Partial Content (WAJIB dimanfaatkan ExoPlayer untuk video). Ada kemungkinan 302 redirect (media di CDN Cloudflare) — OkHttp mengikuti redirect otomatis. Cache-Control panjang — aman di-cache.

### ALUR UPLOAD (3 jalur, cek kemampuan dulu):
1. PROBE: `GET /api/upload/r2-presign` → `{ enabled: boolean }`.
2. Jika enabled (disarankan): `POST /api/upload/r2-presign` body `{ filename, mimeType, size }` → `{ uploadUrl, key, kind, mimeType, maxBytes, maxBytesMB }` lalu PUT file LANGSUNG ke uploadUrl (biner), lalu `POST /api/upload/r2-complete` body `{ key, mimeType }` → `{ mediaId, url, kind, mimeType }`.
3. Jika tidak: file kecil (≤4MB) → `POST /api/upload` multipart field `file` → `{ mediaId, url, kind, mimeType }`.
4. File besar tanpa R2 → pecah jadi potongan 4.194.399 byte (kelipatan 3!): kirim tiap potongan ke `POST /api/upload/chunk` multipart fields `key,index,total,file` → `{ ok, index, total }`; setelah semua tiba `POST /api/upload/complete` body `{ key, totalChunks, mimeType }` → `{ mediaId, url, kind, mimeType }`.

## BAGIAN 11 — SUPABASE + CACHE CLOUDFLARE (perubahan 2026-11)

DATABASE produksi kini dipasang sebagai Supabase (Postgres pooler).
Tidak ada perubahan model/endpoin API sama sekali — hanya infrastruktur.

Env Vercel (mode produksi):
- DATABASE_URL        : URL pooler Supabase port 6543 + `?pgbouncer=true&connection_limit=1&sslmode=require`
                        (db.ts otomatis membersihkan URL; prepare-db.mjs otomatis memilih provider "postgresql")
- MIGRATE_SOURCE_URL  : URL database LAMA (CockroachDB) — HANYA selama proses pindah, hapus setelah selesai
- MIGRATE_SECRET      : teks rahasia untuk membuka endpoint migrasi — HANYA selama proses pindah, hapus setelah selesai
- R2_PUBLIC_URL       : (sudah ada) ganti ke domain custom R2, mis. https://cdn.skelzhub.my.id —
                        media lalu dilayani langsung dari edge Cloudflare (gratis, tanpa fungsi Vercel)

Endpoint BARU admin (sekali pakai saat pindah database):
### GET/POST /api/admin/migrate-db
- Proteksi: header `x-migrate-secret` ATAU query `?secret=` = MIGRATE_SECRET (tanpa env -> 404).
- POST body opsional `{ "sourceUrl": "postgresql://..." }` bila tak mau pakai env.
- Salin semua tabel (User..MediaChunk, urut aman-FK, self-ref dua tahap, ON CONFLICT DO NOTHING -> idempoten).
- Respons: `{ ok, pesan, provider, waktu, tabel: [{tabel, baris, tersalin, selesai, error?}], jumlah_baris: {Tabel:{lama,baru}} }`.
- Kalau `ok:false` karena waktu habis: PANGGIL LAGI, migrasi lanjut tanpa dobel.
- db-setup TIDAK membuat konten demo bila MIGRATE_SOURCE_URL terpasang (migrasi membawa data asli).

Cache (Cloudflare zone skelzhub.my.id):
- Cache Rule 1: URI Path starts_with "/api/media/" -> Eligible, Edge TTL 1 jam (origin sudah kirim Cache-Control public).
- Cache Rule 2: Hostname eq "cdn.skelzhub.my.id" -> Eligible, Edge TTL 1 bulan (objek immutable).
- R2 custom domain cdn.skelzhub.my.id dihubungkan di bucket R2 -> Settings -> Custom Domains.
- DNS www/@ proxy aktif (awan oranye) agar rule berlaku; aktifkan Smart Tiered Cache.

BAGIAN 12 — OPTIMASI v4 (wajib dibaca sebelum lanjut develop)
=====================================================================

A. maxDuration = 60 di SEMUA route API
   - Vercel Hobby default fungsi serverless = 10 dtk; database jauh
     (pooler Supabase Singapura) bisa melewatinya saat sibuk -> fungsi
     dibunuh -> error 500 "terjadi kesalahan server".
   - Semua route kini export const maxDuration = 60.

B. Polling lebih hemat (sumber utama "lag"):
   - badge DM (sidebar/header): conversations 10 dtk -> 30 dtk
   - notifikasi: 15 dtk -> 30 dtk
   - stories: 30 dtk -> 60 dtk (tetap refresh saat kembali ke tab)
   - halaman Pesan: daftar 3 dtk + poll pesan 2 dtk (dipertahankan)
   - poll pesan ?since= TIDAK LAGI menulis DB tiap 2 dtk:
     updateMany readAt hanya saat ada pesan lawan yang belum dibaca.

C. Sinkronisasi chat:
   - kursor "since" TIDAK lagi dihitung dari pesan optimistik (jam client
     bisa lebih maju dari server -> pesan lawan terlewat sampai refresh)
   - kunci in-flight pada tick (tidak tumpang tindih saat jaringan lambat)
   - auto-scroll reset saat pindah percakapan

D. Follow: notifikasi fire-and-forget -> balasan lebih cepat.
   Suggestions: query fallback dilewati bila kandidat populer cukup.

E. UI:
   - shell: rute imersif (shorts/pesan) tanpa pb-[60px] ganda
   - shorts: tinggi 100dvh-118px-env(safe-area) (dulu 124px salah)
   - messages: 100dvh-118px-env(safe-area)
   - post-card: baris aksi px-3/sm:px-4 (sejajar header/caption) + hover
     seragam di 4 tombol; video autoplay mulai BISU (stabil) + tombol suara
   - story ring: overlay absolut (tanpa pertumbuhan layout 6px)
   - animasi story-ring: transform-only (tanpa box-shadow repaint)
   - feed: animasi mount tunggal (stagger CSS dihapus)
   - kolom konten seragam 470px: feed/notifikasi/create/settings

F. create.tsx: dua input terpisah (tombol Ganti media tidak mati lagi),
   fase "Memproses..." setelah unggah, toast tunggal sesuai tahap gagal.
